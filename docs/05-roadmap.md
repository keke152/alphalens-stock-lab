# 扩展路线

v1.2 已实现扩展窗口评估、验证集阈值选择、成本敏感性与自动化持续检查，见 [实现说明](08-v1.2-research.md)。本页其余内容是后续设计方向。建议先强化数据和评估，再增加模型复杂度。

## 第一阶段：让研究口径适配真实数据

### 1. 数据来源登记

为每次导入保存来源、下载时间、标的代码、市场、时区、复权方式和文件摘要。加入交易日历、停牌标记、公司行动信息；明确退市股票和历史成分股如何纳入，避免只研究当前存活标的。

### 2. 市场执行规则

针对 A 股普通股票现货，先重新定义满足 T+1 的持有周期与目标收益，再调整信号执行和回测逻辑。新增持仓状态、资金与股数、最小交易单位、涨跌停无法成交、停牌延迟退出，以及适用的手续费和税费。

不能只将“卖出日期”加一天就认为已经完成适配：多日信号可能重叠，资金占用和持仓合并也需要重新处理。

### 3. 更严格的评估

- 已实现扩展窗口 walk-forward；后续增加固定训练长度的滑动窗口及更多划分选择。
- 每一折独立拟合模型、标准化和概率校准，隔离长度随标签持有期增加。
- 只在过去的训练 / 验证数据上选择参数，保留最后一段完全未触碰的数据。
- 报告不同时间区间的分布及不确定性，避免只报告一个表现最好的区间。
- 加入成本敏感性、参数敏感性、市场状态分组分析。

时间序列交叉验证可参考 [scikit-learn TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)，但交易标签重叠和可获得时间仍需结合业务自行处理。

## 第二阶段：增加研究能力

| 方向 | 实现思路 | 必须先回答的问题 |
| --- | --- | --- |
| 概率校准 | 独立时间段校准、可靠性曲线、Brier 分数 | 校准数据是否完全早于最终测试数据？ |
| 模型比较 | 线性模型、梯度提升、深度序列模型 | 所有模型是否使用同一数据和评估口径？ |
| 特征解释 | 留出集 permutation importance、SHAP | 特征相关性是否让重要性解读失真？ |
| 预测区间 | 分位数回归或适合时间依赖的区间方法 | 区间覆盖率是否在独立数据上验证？ |
| 多标的研究 | 面板数据、历史股票池、组合构建 | 是否引入了存活者偏差和跨标的泄漏？ |
| 更多基准 | 买入并持有、均线规则、随机信号 | 仓位、成本、隔夜风险是否明确一致或注明差异？ |
| 新闻和公告 | 带原始发布时间的数据与文本特征 | 新闻何时实际可获得？修订内容是否回填？ |

LLM 可以辅助解释研究结果、提取公告结构化信息或生成研究报告，但应保留来源，并与数值预测模型、交易执行模块分开。

## 第三阶段：工程化

1. **模型与数据版本：** 记录代码版本、依赖版本、输入摘要、训练日期和模型文件。
2. **任务调度：** 当前已有单线程后台队列与状态查询；可扩展分布式执行、自动恢复、超时与资源隔离。
3. **多人使用：** 用户鉴权、实验权限、上传隔离、审计日志；默认本地模式保持简单。
4. **数据库迁移：** 并发需求出现后再迁移 PostgreSQL；大文件保存到受控对象存储。
5. **部署：** 当前已提供 Dockerfile 与 Compose；可继续补充反向代理、HTTPS、配置管理与监控。
6. **持续检查：** v1.2 已增加计算与真实 HTTP 用例、Python 3.10 / 3.11 工作流；后续扩展系统与浏览器兼容性覆盖。
7. **模型监控：** 数据分布漂移、样本外表现、校准变化和模型失效回退。

## 完成标准

不要把“增加了某个技术名词”作为完成标准。每次扩展都应说明输入、输出、时间可得性、失败方式和可复现依据。例如“支持 A 股”应意味着持有期与成交约束都能解释清楚；“支持在线预测”应意味着训练模型与服务模型的版本、时间边界和更新流程都能追溯。
